# 代码质量与技术债审查

审查日期：2026-10-08。基线为 `6ecc50c`，范围包括 Rust 网关、管理前端、Python 端到端脚本、部署脚本和 CI。本文记录本轮清理后的本地验证结果；CI 配置修改尚待远端执行。

## 当前结论

编译、静态检查和现有功能测试通过。主要问题是构建环境版本不一致、前端缺少独立 lint/格式检查，以及滚动退出和升级测试中的两个时序缺口；本轮已处理。未发现闲置 Rust 依赖，前端未使用文件、导出和依赖检查也已通过。

在后续基于 `4a65970` 的重构中，已完成大型模块拆分和配置契约统一，详见下方记录。通过检查并不等同于完成生产负载、依赖漏洞或安全审计。

## 工具链与持续检查

- `rustup update stable` 确认最新稳定版为 Rust 1.99.0；新增 `rust-toolchain.toml` 固定此版本及 rustfmt/Clippy。Cargo 最低版本要求、Docker 构建镜像、部署镜像探测、CI 和发布工作流统一为 1.99。
- Bun 构建环境统一为已验证的最新稳定版 1.4.2，包含本地、Docker 和 CI。
- Rust 禁止 unsafe，并将死代码、不可达代码作为编译错误；CI 对所有目标和特性运行 Clippy，警告视为错误。新增依赖使用检查、Rustdoc 检查及四项调度压力测试。
- 前端引入固定版本的 Biome 和 Knip，加入 `check`、`lint`、`format:check`、`format`、`deadcode` 命令。类型检查覆盖源码、浏览器测试及构建配置，并检查未使用变量和参数。
- Python 使用仓库内 Ruff 配置；部署脚本使用 ShellCheck、shfmt 和逐文件语法检查；工作流使用 actionlint。上述检查加入 CI 和发布流程。
- 前端先构建、再运行单元测试，确保压缩一致性测试检查本轮生成的资源。生成的 `web/dist` 保持跟踪，不对构建产物手工格式化。

Biome 保留两处有明确原因的规则例外：CSS 的响应式和组件覆盖依赖既有层叠顺序，不启用 `noDescendingSpecificity`；页面切换时滚动到顶部的 effect 保留页面标识依赖，并在该处说明原因。其他启用规则没有未处理警告。

## 本轮清理与修复

| 项目 | 证据与处理 |
| --- | --- |
| Rust 冗余接口 | 删除仓库源码、测试和基准中均无调用的 `HealthState::is_ready` 和 `Node::from_config_with_startup_policy`。保留已使用的构造和路由接口。 |
| 前端未使用导出 | 移除未使用的 i18n 默认导出；将 `statusTone` 和七个仅在定义文件中使用的类型改为内部声明。Knip 检查无剩余问题。 |
| 编辑器行身份 | 模型映射行使用稳定的内部标识，修改或删除其他行时保持现有行身份；标识不写入配置，也不依赖内网 HTTP 页面可能缺少的 `crypto.randomUUID`。 |
| 键盘和表单行为 | 补齐按钮类型、筛选组语义，以及操作菜单的键盘事件隔离；去掉入口根元素的非空断言。 |
| 前端构建提示 | 单独缓存共享 React 运行时：应用主块约 326 kB，React 块约 194 kB。所有 JS 块均低于 500 kB，构建不再出现此前的体积提示。实际首屏 JS/CSS 压缩传输约 200 kB。 |
| 已接受连接的退出竞态 | 原实现在停止接收连接后立即通知 HTTP 层退出，可能关闭已接受但尚未开始首个 HTTP 请求的连接。新增连接进入请求处理的跟踪，并将等待包含在原有退出期限内。可控制时序的回归测试先在旧实现失败，再在修复后通过。 |
| 升级测试的启动竞态 | 流量任务可能尚未开始，升级已经返回，导致零请求断言失败。使用启动同步确保八个任务先发出请求，再开始升级；没有增加重试或固定等待。失败时保留子进程日志到忽略的 `target/test-diagnostics/`。 |
| 部署/Python 脚本 | 修正空 `CDPATH` 赋值、明确子进程返回码处理、整理导入和格式，并使带 shebang 的端到端脚本可执行。 |

## 死代码与实验实现的判定

同步远端并清除失效远端引用后，本地、远端均只有 `main`，且只有当前工作区；没有可删除的实验分支或附加工作区。

没有仅因名称为 legacy 或代码受执行开关控制就删除实现：环境变量凭据兼容、近似前缀回退、通用提供方路由、四项压力测试和性能基准都有实际用途。压力测试和基准已单独执行。CSS 中 `metric-green`、`metric-red` 由动态类名引用，不能按静态字符串搜索结果视为死代码。

Cargo Machete 检查全部 Rust 依赖，没有未使用项。Knip 检查源码、测试、构建和测试配置，没有未使用文件、导出、类型或依赖；构建产物通过项目范围排除。

行数用于说明职责迁移规模，测试和逻辑均保留。Rust 实现通过明确的内部导入连接，各模块测试独立保存。配置类型和全局校验也分开维护。

Rust 配置类型通过可选的 ts-rs 生成 TypeScript，默认值通过 Rust 的 `Default` 序列化；编辑器预设和节点规则同样来自 Rust。前端不再手写节点、提供方、KV、模型能力类型，也不再逐项复制默认值和数值边界。后端与前端解释同一组规则，保留现有配置省略字段和提供方条件规则的行为。

补齐了前端此前漏检的同源管理路径、KV 地址及保留请求头。57 个共享边界用例同时由两端执行，另有直接构造非有限权重的 Rust 回归测试，以及默认值克隆隔离和桌面/手机编辑器回归测试。CI 和发布流程会重新生成到临时目录，发现已提交契约过期时失败。生成工具纳入前端 lint 和类型检查。开发命令与职责说明见 [配置契约文档](config-contract.md)。
