# 代码质量与技术债审查

审查日期：2026-09-11。范围为 Rust 网关、SQLite 存储、管理前端、现有测试和 CI；重点核查状态一致性、异步请求生命周期及配置边界。此次未进行依赖漏洞审计、生产负载测试或逐行安全审计。

## 整体判断

项目已有较好的质量基础：Rust 禁止 unsafe，CI 将 Clippy 警告视为错误；数据库操作通过阻塞线程执行，节点更新使用乐观版本校验；代理、调度、流式响应与滚动退出都有集成测试。主要技术债集中在异步边界、前后端约束重复维护，以及大型模块承担过多职责。

## 已清理

| 问题 | 原有行为与影响 | 本次修复与验证 |
| --- | --- | --- |
| 初始化写入缺少原子性 | `NodeStore::seed_if_empty` 先读取再逐个提交。后续节点校验或唯一约束失败后，前面的节点和控制版本已被保存，再次初始化会因非空而跳过。 | 将非空判断和全部写入放进同一个 SQLite IMMEDIATE 事务，复用插入逻辑。两个新增测试先在旧实现失败，再验证重复 ID、非法配置的整体回滚、版本回滚和失败后重试。当前网关内部通过内存构建路径调用此方法，持久化数据库启动路径不依赖 seed。 |
| 轮询可能长期无法显示慢响应 | 每隔 5 秒创建新请求并推进序号。当接口持续耗时超过 5 秒，已完成结果仍可能被判为过期，且未完成请求不断累积。 | 提取 `useControlPlane`，后台轮询等待当前批次结束；显式刷新取消旧请求；卸载和语言变化清理请求；节点与状态读取设置 15 秒超时。浏览器测试覆盖慢响应、继续轮询、手动刷新、部分失败和恢复。 |
| 整数配置校验不完整 | 前端对部分计数只比较下限，放行 NaN、Infinity、小数和不安全整数；tokenize 缓存条数未校验后端的 65,536 上限。 | 共用整数校验，补齐并发、监控、超时、等待水位、tokenize 缓存和 KV 限额；补齐输入框错误展示和中英文文案。新增 6 项参数与边界测试，在旧实现失败、修复后通过。 |
| 前端缺少未使用代码检查 | `strict` 不检查未使用的局部变量、参数或导入。 | 启用 `noUnusedLocals` 和 `noUnusedParameters`，复用已有 CI 类型检查，无新增依赖。 |

保留并重新生成仓库已跟踪的 `web/dist`，以保证 Rust 内嵌页面与前端源码一致。

- `bun run typecheck`、`bun run build`：通过；构建体积提示见上表。

测试使用临时本地监听端口。最初在受限沙箱中的端口绑定失败属于环境限制；以上 Rust 结果来自允许本地端口的执行环境。未验证 Rust 1.88 工具链、musl 交叉编译或发布部署。
